## 🔐 網路偽裝功能

### 1. TTL 修改 (Time To Live)

#### 什麼是 TTL？
TTL 是 IP 封包的一個欄位，用於限制封包在網路中的存活時間。每經過一個路由器，TTL 值會減 1。

#### 為什麼要修改？
| 設備類型 | 預設 TTL | 特徵 |
|----------|----------|------|
| macOS | 64 | 桌面作業系統 |
| iOS | 64 | 但行動網路行為不同 |
| Windows | 128 | 桌面作業系統 |
| Android | 64/128 | 取決於廠商 |

**問題**：當 MacBook 連接手機熱點時，如果發出的封包 TTL=64，經過手機後變成 63，電信公司就能發現「有裝置在分享網路」。

#### TetherFlow 解決方案
```
MacBook (TTL=65) → 手機熱點 (-1) → 電信公司 (TTL=64)
                                                          ↓
                                              看起來就像手機直接發出的封包！
```

#### 使用方式
1. 在「密碼」區塊輸入系統管理員密碼
2. 點擊「儲存密碼」（僅存在記憶體中）
3. 點擊「啟動偽裝」
4. 系統會自動將 TTL 設為 65

#### 技術實現
```bash
# macOS 使用 sysctl 修改 TTL
sudo sysctl -w net.inet.ip.ttl=65
```

---

### 2. MTU 修改 (Maximum Transmission Unit)

#### 什麼是 MTU？
MTU 是網路介面一次能傳輸的最大封包大小，單位是位元組（bytes）。

#### 為什麼要修改？
| 連線類型 | 常見 MTU | 特徵 |
|----------|----------|------|
| 有線乙太網路 | 1500 | 標準值 |
| Wi-Fi | 1500 | 標準值 |
| 4G/5G 行動網路 | 1420-1400 | 較小，因為封包開銷 |

**問題**：MacBook 預設 MTU=1500，但手機熱點的 MTU 通常較小（1400-1420）。封包大小不一致會被視為「非行動裝置」。

#### TetherFlow 解決方案
將 MTU 設為 **1400**，匹配行動網路的封包特徵。

#### 使用方式
與 TTL 修改同步進行，無需額外操作。

#### 技術實現
```bash
# macOS 使用 networksetup 修改 MTU
sudo networksetup -setmtu Wi-Fi 1400
```

### 3. Profile 管理系統

#### 功能是什麼？
允許使用者建立多組「熱點配置」，每組配置包含：
- SSID（熱點名稱）
- TTL 值（預設 65）
- MTU 值（預設 1400）
- 是否自動啟動

#### 使用場景
```
Profile 1: "iPhone 熱點"
  - SSID: Oscar's iPhone
  - TTL: 65
  - 自動啟動: 是

Profile 2: "公司測試機"
  - SSID: Test-Device-5G
  - TTL: 64
  - 自動啟動: 否
```

#### 操作方式
1. 在「Profile 管理」區塊
2. 點擊「新增 Profile」
3. 填寫熱點名稱和設定
4. 儲存後即可快速切換

## 📡 Wi-Fi 自動偵測

### 功能是什麼？
TetherFlow 會在背景監控 Wi-Fi 連線狀態，當偵測到「已配置的熱點」時，自動啟動偽裝功能。

### 運作流程
```
┌─────────────────┐
│   背景監控線程   │ ← 每 5 秒檢查一次
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  取得目前 SSID   │ ← 使用 airport 或 networksetup
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  比對 Profile   │
└────────┬────────┘
         │
    ┌────┴────┐
    ▼         ▼
┌───────┐  ┌────────┐
│  匹配  │  │ 不匹配  │
└───┬───┘  └────┬───┘
    │            │
    ▼            ▼
┌───────┐  ┌────────┐
│ 自動   │  │ 保持   │
│ 啟動   │  │ 監控   │
│ 偽裝   │  │        │
└───────┘  └────────┘
```

### 啟用方式
1. 在「Wi-Fi 監控」區塊
2. 開啟「啟用 Wi-Fi 監控」開關
3. 選擇「連線時自動啟動偽裝」選項
4. 可選擇是否顯示桌面通知

### 技術實現
```python
# 使用 macOS airport 工具掃描 Wi-Fi
/System/Library/PrivateFrameworks/Apple80211.framework/Versions/Current/Resources/airport -I
```

## 🔒 DNS 加密設定

### 功能是什麼？
將預設的 DNS 伺服器替換為支援 **DoH (DNS over HTTPS)** 或 **DoT (DNS over TLS)** 的加密 DNS 伺服器。

### 為什麼需要加密 DNS？

#### 傳統 DNS 的問題
```
你: "請問 google.com 的 IP 是什麼？"
        ↓
ISP DNS: "是 142.250.185.78"
        ↓
ISP 知道你訪問了 google.com
```

#### 加密 DNS 的保護
```
你: "請問 ████████ 的 IP 是什麼？" (加密)
        ↓
Cloudflare DNS: "████████" (加密回應)
        ↓
ISP 只知道你在用 Cloudflare，不知道你查詢什麼網站
```

### 支援的 DNS 提供者

| 提供者 | 伺服器 IP | 特色 |
|--------|-----------|------|
| **Cloudflare** | 1.1.1.1 / 1.0.0.1 | ⚡ 最快、🔒 隱私優先 |
| **Cloudflare Family** | 1.1.1.3 / 1.0.0.3 | 🛡️ 過濾惡意內容和成人網站 |
| **Google DNS** | 8.8.8.8 / 8.8.4.4 | 🌍 全球最穩定 |
| **Quad9** | 9.9.9.9 | 🔐 安全導向，封鎖惡意網域 |
| **OpenDNS** | 208.67.222.222 | ⚙️ 可自訂過濾規則 |

### 設定方式
1. 進入「DNS 設定」卡片
2. 開啟「啟用加密 DNS」開關
3. 從下拉選單選擇提供者
4. 或選擇「自訂」輸入自己的 DNS 伺服器
5. 點擊「套用設定」

### 驗證 DNS 是否生效
```bash
# 查看目前 DNS 設定
networksetup -getdnsservers Wi-Fi

# 應該顯示你選擇的 DNS 伺服器 IP
```

## 📊 流量整形管理

### 功能是什麼？
**流量整形 (Traffic Shaping)** 是一種頻寬管理技術，可以限制特定連接埠或應用程式的網路速度。

### 為什麼需要流量整形？

#### 使用場景 1：手機熱點工作
```
情境：參加 Zoom 會議，同時 Steam 在下載遊戲

沒有流量整形：
- Steam 占用 20 Mbps
- Zoom 只有 0.5 Mbps
- 結果：視訊卡頓，會議品質差

有流量整形：
- Steam 限制 2 Mbps
- Zoom 保留 5 Mbps
- 結果：會議順暢，背景下載繼續
```

#### 使用場景 2：節省行動數據
```
情境：手機流量只有 10GB/月

限制雲端同步軟體 (Dropbox、Google Drive) 為 500 Kbps
→ 大幅降低背景流量消耗
```

### 如何建立規則

| 欄位 | 說明 | 範例 |
|------|------|------|
| **規則名稱** | 方便識別 | "限制 Steam 下載" |
| **連接埠** | 目標連接埠號 | 27015-27050 |
| **協定** | TCP 或 UDP | TCP |
| **頻寬限制** | 最大速度 | 2000 Kbps (2 Mbps) |
| **啟用** | 是否生效 | 是 |

### 常見應用程式連接埠

| 應用程式 | 連接埠 | 協定 |
|----------|--------|------|
| Steam 下載 | 27015-27050 | TCP/UDP |
| BitTorrent | 6881-6889 | TCP/UDP |
| Dropbox | 443 | TCP |
| Zoom | 8801-8802 | UDP |
| Netflix | 80, 443 | TCP |

### 操作方式
1. 進入「流量整形」區塊
2. 開啟「啟用流量整形」
3. 點擊「新增規則」
4. 填寫連接埠和頻寬限制
5. 儲存後自動生效

## 📈 監控與統計

### 1. 網路速度測試

#### 功能是什麼？
內建網路速度測試，測量：
- **下載速度** (Download Speed)
- **上傳速度** (Upload Speed)
- **延遲** (Ping)

#### 使用方式
1. 在「網路速度測試」區塊
2. 點擊「開始測速」按鈕
3. 等待測試完成（約 30-60 秒）
4. 查看結果和歷史趨勢

#### 技術實現
使用 `speedtest-cli` 工具，連接 Speedtest.net 伺服器進行測試。

## 🛡️ 安全與隱私

### 密碼處理
| 項目 | 說明 |
|------|------|
| **儲存位置** | 僅存在記憶體中 |
| **儲存方式** | Python 變數，不寫入檔案 |
| **生命週期** | 直到應用程式關閉 |
| **重新啟動** | 需要重新輸入密碼 |

### 資料儲存
所有設定儲存在本機 `data/` 資料夾：
- `profiles.json` - Profile 設定
- `dns_settings.json` - DNS 設定
- `traffic_shaping.json` - 流量整形規則
- `session_stats.json` - 統計數據
- `history.json` - 操作歷史
- `speed_tests.json` - 測速記錄

**注意**：這些檔案包含設定但不包含密碼。

## 🚀 快速入門指南

### 第一次使用

```bash
# 1. 啟動後端伺服器
cd web
python3 server.py

# 2. 開啟瀏覽器
open http://localhost:5000
```

### 基本使用流程

```
Step 1: 輸入系統密碼 → 點擊「儲存密碼」
           ↓
Step 2: （可選）建立 Profile
           ↓
Step 3: （可選）啟用 Wi-Fi 自動偵測
           ↓
Step 4: 點擊「啟動偽裝」
           ↓
Step 5: 確認 TTL/MTU 已修改
           ↓
Step 6: 正常使用網路！
```

### 離開時
```
點擊「停止偽裝」→ 系統自動還原 TTL/MTU 設定
```
